# CONTRIBUTING

Правила совместной работы в репозитории для двух разработчиков
(Dev1 — backend, Dev2 — frontend, оба — инфраструктура/CI/деплой).

## Ветки

- `main` — продакшн, защищена (требует PR + зелёный CI).
- `develop` — интеграционная ветка, основная для повседневной работы.
- `feature/backend-<модуль>` / `feature/frontend-<модуль>` — рабочие ветки
  под конкретную сессию или связку из 1–2 сессий одного модуля.

## Коммиты

- Один коммит = один логический шаг сессии.
- Сообщения — на английском, в императиве: `add`, `fix`, `update`
  (не `added`, `fixed`, `updated`).
- Формат для сессионных коммитов: `feat(SXX): краткое описание`,
  например `feat(J02): add CI workflow for backend and frontend checks`.
- Незавершённая сессия: `WIP: SXX — краткое описание того, что осталось`.

## Pull Request

- После каждой сессии (или связки из 1–2 сессий одного модуля) —
  Pull Request из `feature/*` в `develop`.
- PR обязателен даже при работе в одиночку — это чек-лист для
  самопроверки перед мержем.
- **Исключений из этого правила не делаем** — единый архивный коммит
  вместо истории сессий (как это произошло при переносе F01–F09)
  допускается только как разовое, явно задокументированное отклонение,
  не как обычная практика.

## Код-ревью

Обязательно для:
- любых изменений в `alembic/versions/` (миграции);
- `backend/app/core/security.py` (аутентификация);
- всего, что попадает под 152-ФЗ (таблица `User`, `AuditLog`).

Для остального — достаточно самопроверки по зелёному CI
(`ruff`/`mypy`/`pytest` для backend, `eslint`/`tsc` для frontend),
если нет прямого конфликта между модулями.

## Правило «не ломать master»

Каждая сессия завершается состоянием, при котором `docker compose up`
поднимает систему без ошибок, а существующие тесты проходят —
даже если новая функциональность ещё не покрыта тестами.

## Синхронизация между Dev1 и Dev2

Перед началом frontend-сессий, требующих реального backend API
(точки синхронизации КТ-1, КТ-2, КТ-3 — см. `Посессионный_план_IT_Platform.md`,
раздел 5), Dev1 явно сообщает о готовности контракта API.
До этого момента Dev2 работает на моках.
